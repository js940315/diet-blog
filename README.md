# 네이버 다이어트 블로그 자동화

매일 여자 연예인 다이어트 소스를 크롤링 → **제목 1개 자동 확정** → 본문 완성 →
`output/날짜/0번 본문.txt` 에 대기. 아침에 열어서 네이버에 복붙만 하면 끝.

```
run.ps1 (윈도우) / run.sh → main.py
  crawler.py       네이버 검색 API 또는 Google News RSS로 소스 수집
  store.py         인물 45일 쿨다운 / 기사·CTA 중복 차단 (SQLite)
  prompts.py       팩트시트·제목·본문 프롬프트 + 리스크 규칙  ★규칙은 여기 한 곳
  titles.py        제목 10개 → 점수 → 1개 확정   ★핵심
  writer.py        본문 생성 + 자동 수리 루프 (API 경로)
  brief.py         에이전트에게 넘길 지시서 생성 (키 없는 경로)
  draft_to_body.py 평문 초안 → 점자 부착 + 길이 점검
  validator.py     줄수·점자빈칸·단락을 파이썬이 직접 셈  ★핵심
  images.py        팩트시트 → 사진 버킷 선택 → 정사각 가공
  config.py        튜닝은 여기서만

  photo_library.py / image_sourcing.py / build_photo_library.py
                   car-blog에서 가져온 사진 소싱·순환 엔진 (주제 무관, 그대로 재사용)
```

**이미지는 음식 사진만 쓴다.** 카드뉴스(텍스트 얹은 이미지)도, 인물 컷도 쓰지 않는다.
운동·공간 컷은 사람이 크게 나와서 글과 따로 놀고, 남의 몸 사진을 다이어트 글에
붙이는 모양새가 된다. **장수가 모자라면 모자란 대로 내보낸다.**
버킷 목록은 `config.FOOD_BUCKETS_ONLY`, 정사각 1080px로 잘라 가공 없이 나간다.

## 설계 원칙 3개

### ① 제목은 LLM이 고르지 않는다

모델은 10개만 만들고, **선택은 파이썬 점수 함수**가 한다.
홈판은 앞 20자만 노출되므로 총점의 절반 이상이 앞 20자에서 나온다.

```
 110  37년째 53kg 유지한다는 58세 여배우의 아침 식탁
 104  58kg에서 44kg으로, 이혼 후 달라진 44세 여배우 근황
  30  "165cm 43kg" 유지한다는 62세 여배우의 아침 식탁
-999  뼈말라 몸매로 화제된 40대 여배우 다이어트
```

3번이 30점인 이유는 BMI 15.8이라 저체중 스펙(-60)에 걸렸기 때문이다.
따옴표 발언이 앞 20자를 다 잡아먹는 제목도 같은 이유로 낮게 나온다.

**튜닝은 프롬프트가 아니라 `config.WEIGHTS` 숫자로 한다.**
점수 계산이 문서의 실측값과 맞는지는 `python titles.py` 로 확인할 수 있다.

### ② 형식 검증은 프롬프트가 아니라 코드로

모델은 줄을 못 센다. 체크리스트를 100개 넣어도 "통과했습니다"라고 자기보고만 한다.
`validator.py` 가 실제로 세고 → 위반 목록을 되먹여 재작성(최대 3회) →
마지막에 `polish()` 가 기계적으로 강제 복구한다.

검사 항목: 줄 끝 U+2800 부착 / 빈 줄 U+2800×3 / 한 줄 9~19자(권장 13~17) /
한 단락 ≤3줄 / 내용 줄 66~86 / **네이버 공백제외 850~950자(점자 포함·해시태그 제외,
thin은 700~) — 네이버는 점자 빈칸을 글자로 센다(실측)** /
불릿 0개 / 해시태그 정확히 8개 /
소제목 형식(마크다운 기호 노출 0) / CTA 포함 / 수치 아라비아 숫자 /
실명·과잉높임·지침용어 누출 0

> ⚠️ **버그 주의**: 파이썬 `strip()`은 U+2800을 공백으로 인식하지 않는다.
> 빈 줄 판정은 반드시 `line.replace('⠀','').strip() == ''` 로 해야 한다.
> 이거 틀리면 줄 수가 전부 어긋난다. `validator.is_blank()` 가 그 구현이다.

### ③ 못 구하면 뺀다

소스가 얇으면 짧게 낸다. 사진이 없으면 없이 간다.
**억지로 채우는 순간 창작과 리스크가 들어온다.** 이게 이 파이프라인의 기본 태도다.

`crawler.assess_richness()` 가 `thin` 을 반환하면 분량 하한이 64줄에서 48줄로 내려간다.
구글 뉴스 경로는 헤드라인만 얻으므로 대개 `thin` 이 나오는데, 그게 정상이다.

## 설치

```bash
pip install -r requirements.txt
cp .env.example .env    # 키를 채운다
```

**키 없이도 돌아간다.** 있으면 좋아지는 것뿐이다.

| 키 | 없으면 | 있으면 |
|---|---|---|
| `NAVER_CLIENT_ID`/`SECRET` | Google News RSS로 폴백 — 헤드라인만 얻어 근거가 얇다 | 본문 요약까지 얻어 팩트시트가 두꺼워진다 |
| `ANTHROPIC_API_KEY` | 에이전트 경로(`--stage`)로 클로드 코드가 글을 쓴다 | `run.ps1` 한 방으로 끝난다 |
| `PEXELS_API_KEY` 등 | 이미 받아둔 사진 라이브러리를 쓴다 | 라이브러리를 새로 채울 수 있다 |

네이버 키는 developers.naver.com/apps 에서 "검색" API 선택, 무료 25,000회/일.

**사진 키는 라이브러리를 새로 채울 때만 필요하다**: `PEXELS_API_KEY` 또는 `UNSPLASH_ACCESS_KEY`.
매일 쓰는 사진은 이미 받아둔 `assets/photos` 에서 꺼내므로 평소엔 키가 없어도 된다.
Wikimedia/Openverse만으로는 다이어트 소재가 거의 안 나온다 — 실측했더니
"닭가슴살"에 튀김옷 입힌 치킨이 왔다. 음식 컷은 스톡 사이트가 압도적으로 낫다.

## 사진 라이브러리 구축 (첫 실행 전 1회)

```bash
python build_photo_library.py --per 3          # 32버킷 전체 소싱
python build_photo_library.py 샐러드 --per 3   # 한 버킷만
```

받은 뒤 **반드시 눈으로 확인**하고 부적합한 건 파일을 지운 다음:

```bash
python build_photo_library.py --prune
```

수동으로 넣은 사진 등록(파일명 `<버킷명>_아무거나.jpg`):

```bash
python build_photo_library.py --register
```

버킷 목록은 `build_photo_library.py`의 `CATEGORIES` — 테마 8 + 소재 18 + 공간 6 = 32개.
다만 **본문에 실제로 쓰이는 건 `config.FOOD_BUCKETS_ONLY` 의 음식 10개뿐**이다.
나머지는 라이브러리에 남아 있어도 선택되지 않는다.

## 운영 — 경로 A: API (`ANTHROPIC_API_KEY` 있을 때)

```bash
.\run.ps1 --dry-run          # 제목까지만 (첫 실행 권장)
.\run.ps1                    # 풀 생성
.\run.ps1 --celeb 김희선     # 인물 지정
.\run.ps1 --sort date        # 최신 기사 위주 (기본 sim = 옛날 인기 기사 포함)
.\run.ps1 --no-images        # 본문만 (사진 생략)
.\run.ps1 --source google    # 네이버 키가 있어도 구글 뉴스로 강제
```

리눅스·맥은 `./run.sh` 로 똑같이 쓴다. 크론:
```
0 6 * * * cd /경로 && ./run.sh >> logs/daily.log 2>&1
```

## 운영 — 경로 B: 에이전트 (키 없을 때)

파이썬이 수집·제목 점수·형식 검증을 하고, **글 쓰는 일만 클로드 코드가 한다.**
`/daily` 슬래시 커맨드가 이 4단계를 그대로 몰고 간다.

```bash
.\run.ps1 --stage crawl       # → 1_팩트시트_지시서.md
   # 에이전트가 factsheet.json + title_candidates.json 작성
.\run.ps1 --stage title       # 제목 확정 → 2_본문_지시서.md
   # 에이전트가 draft.txt 작성
python draft_to_body.py state\work\<날짜>\draft.txt state\work\<날짜>\body.txt
.\run.ps1 --stage finish      # 검증 → 0번 본문.txt + 사진
```

`--stage finish` 는 위반이 남으면 **종료 코드 4**로 끝나고 `위반목록.md` 를 남긴다.
`draft.txt` 를 고쳐 다시 돌리는 게 정석이고, `--polish` 는 최후 수단이다
(기계가 어절 단위로 잘라서 읽는 맛이 죽는다).

`--date 2026-08-04` 로 지난 폴더를 다시 마감할 수 있다.

클로드 코드 슬래시 커맨드: `/daily`, `/pick 김희선`

산출물 — 아침에 폴더를 열면 복붙할 것만 보인다:

```
output/날짜/1/0번 본문.txt   ← 슬롯 1~10, 슬롯당 본문 1 + 음식 사진 최대 4장
output/날짜/2/ … 10/
state/work/날짜/슬롯/         ← 팩트시트·제목점수·소스 등 (output 밖)

하루 최대 10편(config.DAILY_SLOTS). 지속 조건 = 인물 풀 ÷ 쿨다운 ≥ 10
(현재 180명 ÷ 15일 = 12). 소스 10건 미만 인물은 자동 스킵·쿨다운 처리.
```

## 자체 테스트 (키 없이 실행 가능)

```bash
python titles.py            # 제목 점수가 문서 실측값과 맞는지
python validator.py         # 망가진 입력의 검출·복구 + 면책 문구 삽입
python store.py             # DB 초기화 + 쿨다운/CTA 상태
python crawler.py 김희선    # 실제 수집 (키 없으면 구글 뉴스로 폴백)
python images.py            # 팩트시트 → 사진 버킷 선택 로직
```

## ⚠️ 이 주제 고유의 리스크

다이어트·연예인은 **지금 규제 당국이 활발히 단속 중인 영역**이다.
아래는 `prompts.py` 에 규칙으로 박혀 있고, 일부는 `validator.py` 가 실제로 검사한다.

**실존 인물**
- 몸에 대한 평가·추측 금지. "살쪘다/망가졌다" 류는 명예훼손·모욕 소지가 있다.
- 쓸 수 있는 건 **본인이 공개적으로 밝힌 발언**의 인용과 요약뿐.
- 사진만 보고 추정한 체중 변화, 건강 상태 추측, 익명 커뮤니티발 주장은 금지.
- 인용에는 방송 프로그램명이나 매체명을 본문에 밝힌다
  (`factsheet.quote_sources` 가 그 자리다. 출처가 없으면 그 발언은 버린다).

**건강 정보**
- 효과를 단정하지 않는다. "○○하면 살 빠집니다"(X) → "○○했다고 밝혔습니다"(O)
- 처방의약품은 아예 다루지 않는다 (`BANNED_HOOKS` 에 걸리면 제목·본문 모두 탈락).
- 특정 제품·보조제를 추천하는 구성으로 가지 않는다.

## 안전 가드 (기본 ON, config에서 끌 수 있음)

- `AD_DISCLOSURE` / `HEALTH_DISCLAIMER` — **기본 OFF (2026-08-04 사용자 결정).**
  켜면 `validator.ensure_notices()` 가 해시태그 앞에 안내 문구를 붙인다.
  쇼핑커넥트(대가성 링크)를 실제로 붙이는 날에는 `AD_DISCLOSURE` 를 다시 켜야 한다 —
  공정위 추천·보증 심사지침 대상이라 표기 없이 링크만 넣으면 리스크가 매일 쌓인다.
- `BMI_FLOOR = 17.5` — 저체중 스펙 병기 시 -60점.
  대신 유지기간형이 +18로 최고 가중치라 화력 손실은 거의 없다.
- `EXTREME_WORDS`(뼈말라·앙상 등) / `BANNED_HOOKS`(약물·시술·단식원·원푸드) — 걸리면 탈락.
- **실명은 제목 블라인드 / 본문 도입부 리빌.** 제목에 나오면 그 제목은 탈락하고,
  본문 도입부에 리빌이 없으면 검증기가 잡는다. 다른 여자 연예인 실명은 본문에도 금지.
