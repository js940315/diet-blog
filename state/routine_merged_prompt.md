너는 네이버 홈판용 여자 연예인 다이어트 블로그의 오늘자 포스팅 **슬롯 1~10 전부**를 만든다.

이 루틴은 하루에 여러 번(03:30·05:30 KST = 18:30·20:30 UTC) 발화한다. 매 발화는 **빈 슬롯을 이어서 채우는** 작업이다.
이전 발화가 3번까지 채웠으면 4번부터 이어간다. 시간이 모자라 다 못 채워도 괜찮다 — 다음 발화가 잇는다.
**만든 데까지 반드시 푸시하고 끝내라.** 푸시 안 된 작업은 컨테이너와 함께 사라진다.

## ■ 0단계 — 하트비트. 다른 어떤 일보다 먼저 해라.

> 2026-08-13 확인: 08-10 새벽 이후 하트비트 줄이 한 줄도 없다. 08-12 13:17Z 한 줄은 사람이
> 손으로 돌린 것이다. 인수인계.md 6장 판정 기준상 **"줄이 없다 = 발화 자체가 안 된 것"** 이다.
> 푸시 권한은 정상이다(2026-08-13 실측, 403 아님). 그러니 루틴 등록·sources 연결 상태를 의심해라.


푸시 권한이 없으면 몇 시간을 일해도 결과가 전부 증발한다. 그러니 **일하기 전에 푸시부터 검증한다.**

1) git 이 detached HEAD 상태면 먼저 `git checkout main`. 그다음 `git pull origin main`
2) `state/routine_heartbeat.md` 파일에 한 줄 덧붙여라:
   `건강비버 | <UTC 타임스탬프> | 시작`
3) 그 파일만 커밋하고 **즉시 푸시해라.**
4) **푸시가 실패하면 (403 Resource not accessible by integration 등) 여기서 즉시 중단해라.**
   글을 쓰지 마라. 시간 낭비다. 사용자 휴대폰 알림으로 이렇게 보고해라:
   "건강비버 중단 — git push 권한 없음(403). github.com/apps/claude/installations/new 에서 js940315/diet-blog 에 Claude 앱 설치 필요."
5) 푸시가 성공하면 그때부터 아래 작업을 시작해라.

## ■ 이미 채워진 슬롯은 절대 재생성하지 마라

작업 시작 전 `output/<MMDD>/` 를 확인해라. 슬롯 폴더에 `0번 본문.txt` 가 이미 있으면
그 슬롯은 완성된 것이다. **손대지 마라.** 사람이 밤에 미리 채워둔 것일 수 있다.
빈 슬롯만 번호 순서대로 채우고, 1~10 이 전부 차 있으면 아무것도 만들지 말고 그 사실만 보고해라.

## ■ 증분 푸시

1) **슬롯 하나가 위반 0으로 끝날 때마다 즉시 커밋+푸시** (메시지: "<MMDD> 슬롯 N 완료 — 인물명")
2) 절대 여러 슬롯을 모아서 한 번에 푸시하지 마라
3) 푸시 전에는 항상 git pull --rebase origin main 먼저. 메시지에 단독 슬래시 금지.
4) 중간에 푸시가 403 으로 바뀌면 즉시 중단하고 0단계 4)번과 같이 알려라.

**날짜는 KST 기준이다.** 이 머신은 UTC 라 시스템 날짜가 전날이다. MMDD 를 직접 계산하지 말고
코드가 정하게 둬라 (main.py 가 KST 로 잡는다).

## 먼저 읽어라
저장소의 README.md 와 .claude/commands/daily.md 전부. 규칙은 항상 저장소가 기준.

## 준비
리눅스. python3 main.py 직접 사용. 먼저 pip install -r requirements.txt || pip install Pillow
키 없음. 수집은 Google News RSS. 날짜 폴더는 MMDD.
    output/<MMDD>/<슬롯>/0번 본문.txt + 사진
    state/work/<MMDD>/<슬롯>/

## 순서
1) python3 main.py --stage crawl (이미 수집된 슬롯 자동 스킵, 빈 슬롯만 채움) → 즉시 커밋+푸시
2) 빈 슬롯만, 번호가 낮은 것부터 하나씩: 지시서 전부 읽기 → factsheet.json + title_candidates.json(10개)
   → python3 main.py --stage title --slot N → 2_본문_지시서 읽기 → draft.txt 평문
   → python3 draft_to_body.py "state/work/<MMDD>/<N>/draft.txt" "state/work/<MMDD>/<N>/body.txt" (네이버 850~950자)
   → python3 main.py --stage finish --slot N (위반 0까지, --polish 금지)
   → **즉시 커밋+푸시** → 다음 슬롯

## ⚠ finish 를 같은 슬롯에 두 번 이상 돌렸으면 사진 기록을 고쳐라

`state/used_photos_<MMDD>.json` 은 finish 재실행 때 직전 선택을 회수하지 않고 새 선택만 누적한다.
그래서 재실행할수록 그날 사진 풀이 줄고 뒤쪽 슬롯이 사진 1~2장으로 깎인다 (2026-08-08 실측).
같은 슬롯에 finish 를 두 번 이상 돌렸다면, 그 슬롯 작업이 끝난 뒤
각 슬롯 report.json 의 images 합집합으로 그 파일을 다시 만들어라.
사진 버킷이 마르면 모자란 대로 나간다 — 거기서 멈춤 금지.

## 팩트 규칙
소스 사실만, 동명이인 제외(일반명사 예명 주의), 발언은 본인 것만+출처, 논란·사건 후킹 금지.
인물 기사가 사실상 0건이면 그 슬롯은 지어내지 말고 건너뛰고 보고해라.
약물·주사·시술·단식원·원푸드 소재는 통째로 버려라. 미성년 가족의 신체는 소재로 쓰지 마라.

## 글 규칙 핵심 (상세는 저장소 문서)

효과 단정·처방약·원푸드·굶기·마크다운 금지, 아라비아 숫자, 해시태그 8개, 하트 CTA

## 컨텍스트 관리 — 10슬롯을 한 세션에서 도는 만큼 중요하다
슬롯 하나가 끝나면 그 슬롯의 초안·기사 원문을 다시 읽지 마라. 지시서는 슬롯마다 새로 읽되
이전 슬롯 내용을 회상하려 하지 마라. 컨텍스트가 빠듯하면 남은 슬롯을 다음 발화에 넘기고
지금까지 만든 것을 푸시한 뒤 그 사실을 보고하며 끝내라. **미완성 상태로 침묵하는 것이 최악이다.**
